ISM POS Documentation

A modern, fully offline-capable Point-of-Sale desktop application built with Tauri 2, Next.js 16, shadcn/ui, Tailwind CSS v4, and Zustand. Ships as a native Windows, macOS, or Linux binary with a zero-external-server architecture.

⚡ Tauri 2 ⚛️ Next.js 16 🦀 Rust backend 🎨 Tailwind CSS v4 🐻 Zustand 5 🧩 shadcn/ui

Tech Stack

⚡

Tauri 2

Native desktop shell. Hosts the Next.js static export in a WebView. Handles system-level IPC commands via Rust.

⚛️

Next.js 16 (static export)

React 19 app compiled to a fully static HTML/JS bundle. No Node.js server required at runtime.

🦀

Rust Backend

Handles OS-level tasks: device info, versioning, health checks. Exposed to the UI via Tauri IPC commands.

🎨

Tailwind CSS v4

Utility-first CSS with OKLCH colour tokens. Light/dark theme switching via next-themes.

🧩

shadcn/ui + Radix

Accessible, unstyled primitives (dialogs, sheets, dropdowns) styled with Tailwind. Fully copy-owned in src/components/ui/.

🐻

Zustand 5

Lightweight global state for cart lines and UI flags. Cart is persisted to localStorage via the persist middleware.

Setup & Development

Prerequisites

  • Node.js ≥ 20 (LTS recommended)
  • Rust + Cargo — install via rustup.rs
  • Tauri CLI — installed automatically as a devDependency
  • Windows: WebView2 (pre-installed on Windows 11, available via Microsoft for Windows 10)

First-time setup

# 1. Install JavaScript dependencies
npm install

# 2. Generate application icons (pure Node, no canvas required)
npm run tauri:icon

# 3. Start the full Tauri dev session (Next.js dev server + Rust watcher)
npm run tauri:dev

Frontend only (browser)

npm run dev
# Open http://localhost:3000
ℹ️ Running in the browser The app works fully in the browser. Tauri-specific features (device info, version badge) are gated by the isTauri() guard in src/lib/tauri.ts and degrade gracefully.

View documentation

npm run docs
# Open http://localhost:4400

Frontend Architecture

Rendering model

Next.js is configured with output: "export", which compiles the entire app into a static /out directory. Tauri's frontendDist points to this directory for production builds. No Node.js server is needed at runtime.

Routing

The app currently uses a single-page architecture. The root route (/) renders the full POS experience via AppShell. Additional routes (Dashboard, Orders, etc.) are stubs in the nav config and will be wired to separate Next.js pages in future sprints.

Theme system

Colour tokens are defined as OKLCH CSS custom properties in globals.css. The AppProviders component wraps the app in next-themes ThemeProvider, which toggles the .dark class on <html>. The theme toggle button in the Topbar calls setTheme().

Backend Architecture

The Rust backend lives in src-tauri/src/. It exposes a small set of Tauri commands (RPC handlers) that the frontend calls via the IPC bridge. The backend has no database — all transactional state lives in the frontend stores. Future sprints may add SQLite via tauri-plugin-sql.

Entry points

  • main.rs — binary entry point; calls lib::run()
  • lib.rs — registers plugins and command handlers with tauri::Builder
  • commands.rs — all #[tauri::command] implementations

IPC Bridge

Communication between the WebView (TypeScript) and the Rust process uses Tauri's typed invoke API. The frontend wrappers in src/lib/tauri.ts provide a clean, promise-based API. 

// TypeScript side
import { invoke } from "@tauri-apps/api/core";

export async function getAppVersion(): Promise<string> {
  return invoke<string>("get_app_version");
}

// Rust side (commands.rs)
#[tauri::command]
pub fn get_app_version() -> String {
    option_env!("CARGO_PKG_VERSION")
        .unwrap_or("unknown")
        .to_string()
}
✅ isTauri() guard All IPC calls are wrapped with isTauri() which detects window.__TAURI_INTERNALS__. If the app runs in the browser, IPC calls are skipped and the UI degrades gracefully (no version badge, demo-mode checkout toast).

State Management

Global state is managed with Zustand 5. Two stores are used:

useCartStore

Cart lines, payment method, add/remove/update/clear/checkout. Persisted to localStorage under the key ism-pos-cart.

useUiStore

Search query, active category filter, cart sheet open state, sidebar sheet open state. Not persisted.

Tauri IPC Commands

All commands are registered in src-tauri/src/lib.rs and implemented in commands.rs. Call them from TypeScript via the wrappers in src/lib/tauri.ts.

Command Arguments Returns Description
greet name: string string Classic smoke-test. Returns a greeting confirming the desktop shell is alive.
get_app_version — string Returns the CARGO_PKG_VERSION at compile time, displayed in the Topbar.
get_device_info — DeviceInfo Returns OS name, platform, architecture and a rough uptime value for display in system diagnostics.
ping — PingResponse Health check used during checkout to confirm the IPC bridge is live. Returns { ok: true, message, timestamp }.

DeviceInfo

interface DeviceInfo {
  name: string;         // COMPUTERNAME / HOSTNAME
  platform: string;     // "windows" | "macos" | "linux"
  version: string;      // currently maps to arch (future: OS build)
  arch: string;         // "x86_64" | "aarch64"
  uptime_seconds: number;
}

PingResponse

interface PingResponse {
  ok: boolean;       // always true when reachable
  message: string;   // "Pong — Rust backend reachable"
  timestamp: number; // Unix epoch seconds
}

Key Components

AppShell

src/components/layout/app-shell.tsx
Root layout wrapper. Renders the desktop three-column layout (Sidebar + main + CartPanel) and mobile sheet overlays. Reads sidebarOpen / cartOpen from useUiStore.

Sidebar

src/components/layout/sidebar.tsx
Icon-only on small screens, full-width on lg+. Nav items driven by siteConfig.nav. Shows operator name and version at the bottom.

Topbar

src/components/layout/topbar.tsx
Sticky header with page title, search input (hidden on mobile), dark-mode toggle, and a cart button for mobile users. Fetches app version from Tauri on mount.

ProductGrid

src/components/pos/product-grid.tsx
Renders CategoryFilter + a responsive grid of ProductCards. Shows skeleton loaders for 350 ms on first paint. Filtered by selectFilteredProducts.

ProductCard

src/components/pos/product-card.tsx
Emoji tile with gradient background, product name, description, price, and a quick-add button. Calls addItem() on click.

CartPanel

src/components/pos/cart-panel.tsx
Scrollable list of CartItemRows, subtotal / tax / total summary, payment method selector, and a charge button. Calls pingBackend() on checkout to detect desktop mode.

StatsBar

src/components/pos/stats-bar.tsx
Four KPI cards (Today's Sales, Orders, Avg. Order, Items Sold) with trend indicators. Currently uses static seed data; wire to a Rust command or API in a future sprint.

⚠️ Static export requirement Because next.config.ts sets output: "export", you cannot use Next.js Server Components, API Routes, or Server Actions. All data must be client-side or passed via Tauri IPC commands.

Icon Generation

Icons are generated by scripts/generate-icons.mjs — a zero-dependency Node.js script that synthesises RGBA PNG buffers and wraps them into .ico (Windows) and .icns (macOS) containers using only Node built-in modules (zlib, fs).

Generated files

  • src-tauri/icons/32x32.png
  • src-tauri/icons/128x128.png
  • src-tauri/icons/128x128@2x.png
  • src-tauri/icons/icon.png (512 × 512 source)
  • src-tauri/icons/icon.ico (Windows)
  • src-tauri/icons/icon.icns (macOS)
  • Windows Store variants: Square30x30Logo.png, Square44x44Logo.png, Square107x107Logo.png, StoreLogo.png
